# 场景验收与交付

## 数据与场景保护

- Original JSON及PNG的SHA256与manifest.json相同。
- 原点位经统一坐标变换后XY不变，新增Z与物体数据独立保存；变换必须有至少三个不共线锚点校准。
- 不直接用图片像素除以3覆盖JSON：标题偏移、图像标注和数据差异需要分别处理。
- 各区域中心和半径不是精确地形边界；保留PNG整体不规则轮廓和原连通关系。

## 每区必须交付

1. 一张实际固定游戏镜头，角色处于可活动中景；六区至少六张，注明玩家位置。
2. module_requirements中每项都对应实际关卡对象；记录正式资产/占位、材质、碰撞、是否淡出。实例数量不是质量通过条件。
3. 连续地面、侧面厚度、路外体量和植被层级；活动区保留净空，背景不能压住关键玩法信息。

## 专项运行测试

| 项目 | 通过条件 |
|---|---|
| 基地往返 | 按原布局完成至少三次外出采集返回，无地面裂缝、卡脚与相机变化 |
| 建造 | 用项目实际建筑占地试摆；没有建筑系统则使用明确标记的碰撞/占地代理；设施入口与通道始终清楚 |
| 瀑布 | 崖顶、液流、落潭、溪槽与门口关系完整；边缘与碰撞阻止绕过强制门 |
| 哨戒缝 | 两侧陡坡/菌丝封边，不能借装饰跳过原规则 |
| 腐败区 | 压力板桥有桥下深度和接岸；可选绕行仍通；坍塌孔与主动深渊入口有清楚区别 |
| 地下 | 入口落点与祭坛场地可活动；洞顶不持续遮挡玩家；不新增未确认钥匙或出口机制 |
| 局部渐隐 | 菌盖/屋顶/墙片多层均处理，同资产其他对象不受影响，离开恢复且无闪烁 |
| 交互可读 | 角色与当前可操作目标均可读；仅角色检测的候选代码不自动视为已通过目标遮挡 |
| 碰撞与相机 | 淡出不改碰撞/导航；方位、距离、投影参数无变化，无新增缩放 |
| 生命周期 | 死亡、重生、切图、结束PIE后材质无错误残留 |
| 持久化 | 保存并关闭重开候选关卡，布置、引用及代码配置仍有效 |

## 最终目录建议

提交`SceneReport.md`、`SourceDiscrepancies.md`、`PlacementManifest.json`、`DepthOverrides.json`、`CameraBaseline.json`、`TestResults.md`及`Captures/`。每条布置必须有区域、类别、源锚点、新增地面Z、关卡对象路径、网格/材质、替代说明和验证状态；代码未编译、玩法未接入、占位未替换分别列明。

截图包含六区总览与瀑布/门、哨戒缝、桥上下层、深渊交互、遮挡前后专项。录制实际相机下的移动及返回流程。无法录制时明确工具限制，不用虚构视频链接代替。
