# 深渊之孔：单向确认入口代理

`DepthAbyssPortalProxy.h/.cpp` 定义本图专属 `ADepthAbyssPortalProxy` 和纯文字 `UDepthAbyssPromptWidget`。这是交互代理，不是正式过场、正式传送系统、陷落陷阱或钥匙机制。尚未编译/运行，需由集成任务更新验收结果。

Actor 放在源 `hole_abyss` 的安全接近点，入口边缘防跌落护栏由场景搭建提供。该 Actor 不创建触发坠落，也不去掉碰撞。默认交互距离 350 cm，可调。

优先设置 `UndergroundDestinationActor` 为地下独立安全落点的 Actor（位置应为角色胶囊中心高度并留出净空）。也可设置 `UndergroundDestination` 为 **UE 世界坐标厘米**，并开启 `bDestinationConfigured`。未配置时只显示“入口暂未开放”，不允许误传到原点。

靠近时显示 E 提示；按 E 显示“跳下去，前往世界深层？”及单向提示；Enter 二次确认后调用带碰撞检查的 `TeleportTo`。Esc 或离开范围取消确认。玩家需要在地面且没有翻滚，避免翻滚根运动与传送叠加。落点被阻挡时不传送，显示重试/取消提示。成功后停止原有点击移动路径及旧速度，但不改相机、朝向、输入模式或共享角色。没有回程入口、钥匙门槛和未经需求确认的自动坠落传送。

UI 只读按键状态并显示无点击拦截的 UMG 文本，不启用 Actor 输入组件，不夺取键盘焦点、不吞掉共享玩家输入。现有 Build.cs 已包含 InputCore、UMG、Slate；本地 Slate 公共依赖中有 SlateCore，因此无需新增模块。未来若移除现有 Slate 依赖，需重新检查 UI 依赖。

运行时诊断属性：`player_in_range`、`awaiting_confirmation`、`confirmed_entry_count`、`last_entry_error`。公开接口 `request_entry_confirmation()`、`confirm_entry()`、`cancel_entry()` 与 E/Enter/Esc 使用同一实现，不能直接绕过确认链传送。

建议 PIE 用真实落点依次检查：

1. 范围外直接 `confirm_entry()` 返回 false、位置不变。
2. 靠近入口且站地面，E 只显示确认，位置不变；离开范围后确认自动清除。
3. 回到入口，`request_entry_confirmation()` 后 `cancel_entry()`，再确认仍返回 false。
4. E 后 Enter 成功到地下；胶囊没有嵌入碰撞体，`confirmed_entry_count` 增加 1，旧寻路和速度清除，相机设置保持基线。
5. 临时阻塞地下落点后请求确认，应失败并留在源端；测试阻挡体仅放于 PIE，完成后清理。
6. 站在边缘不按 E，不会传送；护栏阻止意外直接跌入。
7. 确认等待期间死亡/重生/换 Pawn，旧确认作废；停止 PIE 后提示消失。

编辑器默认 Escape 可能直接结束 PIE；键盘取消 UI 的正式运行行为应在 Standalone 或调整了编辑器停止快捷键的测试环境核对。本实现没有擅自改动编辑器快捷键。PIE 内可用公开 CancelEntry 跑同一取消逻辑，但这不等于实际 Esc 键盘测试已通过。
