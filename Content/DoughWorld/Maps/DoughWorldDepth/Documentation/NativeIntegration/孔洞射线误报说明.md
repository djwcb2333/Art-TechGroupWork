# Editor Visibility 射线会命中无孔编辑器辅助地形

2026-09-10 审查 `HoleMaskDiagnosis.json`：RT 的四孔与桥下中心红值均为 1，两处实体为 0；材质与孔洞材质均是带 LandscapeVisibilityMask 的候选地形材质，无组件孔洞材质覆盖；原生接受导入，完整更新后 Editor Visibility 射线仍命中地形。

本机 UE 5.8 `Runtime/Landscape/Private/LandscapeCollision.cpp` 给出了独立原因：

- 460—488 行：非 GameWorld 且非 cooked-for-editor 时，额外创建 `EditorHeightfieldGeometry` 碰撞形状，只阻挡 `ECC_Visibility`，其余通道忽略。
- 633 行明确说明 Editor heightfield 不含材质索引，因此没有孔洞。
- 943—947 行以 default-material-only 模式生成此编辑器形状，目的是让编辑器在孔洞内仍可编辑地形。

所以当前 `verify_editor.py` 的 EditorWorld + ECC_Visibility 不能作为玩法孔洞碰撞验收。此时继续改写权重或移除整个地形碰撞会破坏正确数据。

新增只读 `verify_holes_game_collision.py`：编辑器中改用 Camera 通道，分别检查 simple/complex，并用两处实体命中验证通道确实有效；PIE 中额外检查 Visibility。报告区分 EditorCamera 与 PIE。这些检查通过后，才可以判断原来的五个 Visibility 命中是编辑器辅助形状造成的误报。此审查本身不声称运行测试已经通过。
