# UE 5.8 Visibility 层导入桥接

新增 `DepthLandscapeTools.h/.cpp`，复制模块根目录。`GDATtest.Build.cs` 的 PublicDependencyModuleNames 新增 **Landscape**；Engine 已存在，不需要 LandscapeEditor 或 UnrealEd 依赖。本函数是反射可见的编辑器操作，非编辑器构建只返回 false；不包含运行时地形修改能力。

Python 调用：`unreal.DepthLandscapeTools.import_visibility_mask(landscape, render_target, 0)`。

必须满足：当前编辑器世界和 Landscape 关卡在 `/Game/Maps/DoughWorldDepth/` 下，非 PIE；RenderTarget 资源已初始化、宽高至少等于地形顶点数；指定 edit layer 存在。任何代理或待修改权重图属于候选目录之外均拒绝，防止复制地图后继续共用原图权重纹理。World Partition 自动生成的本候选 `__ExternalActors__` 包允许使用。

红通道 0 表示实体地面，1 表示孔洞。坐标方向和绘制材质由生成脚本明确；不要将“可见=1”的一般 Alpha 定义误用于 Landscape Visibility 权重。材质依然必须将 LandscapeVisibilityMask 接到 Opacity Mask 并使用 Masked 模式，否则仅写入数据不能证明孔洞正确渲染。

原因已对照本机 `Landscape.cpp` / `LandscapeEdit.cpp`：5.8 的 `UpdateLayerInfoMapInternal` 只重建已有 TargetLayers；Visibility 仅在已存在键而 LayerInfo 为空时补对象，因此新地形的字符串导入可能找不到此层。桥接先调用 `CreateTargetLayerSettingsFor(ALandscapeProxy::VisibilityLayer)` 注册引擎专用对象，再刷新映射，随后复用原生 `LandscapeImportWeightmapFromRenderTarget`，不创建同名普通涂层、不重复实现 GPU 读回或 AlphaAccessor。

外层事务、Modify 和保存由调用 Python 负责。原生导入函数自己还有内部 ScopedTransaction；Python 的外层事务应覆盖注册 Visibility 和导入两步。建议先对 Landscape、LandscapeInfo、受影响组件执行 Modify，调用后等待地形/碰撞更新、保存候选地图，再重载并验证孔洞内部射线不命中地表、孔洞外仍命中地表。函数返回 true 仅表示编辑层导入被接受，不能代替最终碰撞/画面验证。

本机此导入 UFUNCTION 没有 `LANDSCAPE_API` 导出，跨模块直接调用会链接失败。包装器通过 `FindFunction` 和 `ProcessEvent` 分派；`FStructOnScope` 按真实反射布局分配参数，分别查找 `InRenderTarget`、`InLayerName`、`InEditLayerIndex`、`ReturnValue` 的类型和偏移，不使用手写参数结构猜测对齐。
