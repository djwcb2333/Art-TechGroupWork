# 蓝图玩法扩展指南

本文件说明资源、敌人、窝点和酒精攻击的蓝图扩展接口。底层背包事务、生命值结算、计时和存档仍由 C++ 执行；蓝图可以修改判断规则、数值计算和表现流程。玩家、UI 的接口以各自交接说明为准。

## 编辑入口

玩法蓝图根目录：`/Game/DoughWorld/Maps/Gameplay/Blueprints`。

| 需要修改的内容 | 蓝图 |
|---|---|
| 水、酵母、面团、面粉采集点 | `Resources/BP_DWResource_Water`、`BP_DWResource_Yeast`、`BP_DWResource_Dough`、`BP_DWResource_Flour` |
| 敌人 | `Combat/BP_DWEnemy` |
| 敌人窝点 | `Combat/BP_DWEnemyNest` |
| 酒精持续伤害区域 | `Combat/BP_DWAlcoholArea` |
| 飞行中的酒精瓶 | `Combat/BP_DWAlcoholProjectile` |

只调整生命、半径、速度、周期、数量和伤害时，打开蓝图的 **Class Defaults / 类默认值** 修改对应分类即可；场景中单个实例支持 `EditAnywhere` 的参数也可单独改。减速的 `SlowPercent` 使用 **0–100**，例如 30 表示减速 30%。资源物品 ID 使用 `Water`、`Yeast`、`Dough`、`Flour`、`Alcohol`。

要增加判断或表现，打开 **My Blueprint / 我的蓝图 → Overrides / 重写** 查找下表中的规则函数；通知事件可在 Event Graph 中右键搜索。规则函数属于 `BlueprintNativeEvent`，不重写时自动执行默认 C++ 规则。通知属于 `BlueprintImplementableEvent`，默认没有额外行为。

## 规则函数：只计算结果

规则函数被声明为纯函数。不要在其中增减物品、扣血、生成敌人或播放一次性奖励；它们可能被扫描或 UI 查询多次。

| 类 | 可重写函数 | 默认实现与调用时机 |
|---|---|---|
| ResourceNode | `CanHarvest() → bool` | 默认 `true`。`IsAvailable()` 在检查物品 ID、批量数量和剩余库存之后调用它；因此现有玩家扫描及按住 F 流程会自动使用此规则。可以临时禁止某个资源点。库存已空时，返回 `true` 也不会重新获得资源。 |
| EnemyCharacter | `CanDetectTarget(Target) → bool` | 默认检查目标有效、位于 `DetectionRadius` 内且符合视线要求。在尚无追踪目标时执行。想保留默认距离和遮挡判断，可先调用 Parent 实现，再与附加条件相与。 |
| EnemyCharacter | `CanAttackTarget(Target) → bool` | 默认检查 `AttackRange`、高度差及视线。已有追踪目标时执行；返回 `false` 会继续追踪，返回 `true` 切到攻击状态。实际攻击仍受 `AttackInterval` 控制。 |
| EnemyCharacter | `GetAttackDamage(Target) → float` | 默认返回 `AttackDamage`。每次攻击冷却满足、即将结算时调用；只返回最终伤害数值，C++ 随后执行一次 `ApplyDamage`。 |
| EnemyNest | `CanSpawnEnemy() → bool` | 默认 `true`。出生计时满足后，在窝点存活、EnemyClass 有效、未超过 `MaxAliveEnemies` 等检查后调用。可以暂时关闭窝点；返回 `true` 不会绕过死亡或数量限制。 |
| AlcoholArea | `CanAffectTarget(Target) → bool` | 默认 `true`。每次区域结算，对范围内存活的敌人或窝点逐一调用；返回 `false` 会跳过该对象本轮的伤害、减速和变身奖励。无法用此函数把玩家变成攻击目标。 |
| AlcoholArea | `GetDamageForTarget(Target) → float` | 默认返回 `DamagePerTick`。对象通过筛选后调用，然后由 C++ 结算一次伤害。可按敌人类别返回不同数值。 |
| AlcoholProjectile | `CalculateLaunchVelocity(Target) → Vector` | 默认依据 `FlightTime`、`MaxThrowDistance` 和重力计算抛物线初速度。发射时调用一次；只返回速度，C++ 负责真正启动 ProjectileMovement。没有重写时保留现有瓶子轨迹。 |

`CanHarvest` 没有传入采集者参数，适合资源点本身的开关或状态判断。若以后要按不同玩家或 NPC 分别判断，需要在玩家的交互入口再加对应规则，不能在采集成功通知中事后撤销物品。

## 通知事件：核心动作已经执行

以下事件用于动画、音效、特效、材质变化和 UI 提示。除非明确在设计一个额外动作，不要在通知中再次调用对应的扣血、加物品、提交或出生函数。

| 类 | 事件 | 确切调用时机 |
|---|---|---|
| ResourceNode | `OnHarvestCommitted(ActualAmount)`（已有） | 玩家背包已成功接收物品，资源节点已按实际数量减少库存并刷新显示之后。无限点不会扣减库存。可显示获得数量或播放采集反馈。 |
| ResourceNode | `OnAvailabilityChanged(bAvailable)` | BeginPlay 初始化一次；成功提交或恢复存档后，可采集状态发生变化时再通知。单纯恢复显示也可能触发，不能把它当成获得物品事件。 |
| EnemyCharacter | `OnStateChanged(PreviousState, NewState)` | 实际状态从 Patrol、Chase、Attack、Dead 中一个切换至另一个时，仅调用一次。适合切换动画状态、警觉图标或材质。初始 Patrol 不重复广播；读档恢复死亡状态静默执行，避免再次奖励。 |
| EnemyCharacter | `OnEnemyAttack(Victim)`（已有） | 一次近战攻击已经尝试结算，并已执行默认攻击音效之后。它表示一次攻击动作，不能据此再扣一次血。 |
| EnemyCharacter | `OnAttackResolved(Victim, ActualDamage)` | 紧接攻击通知之后；`ActualDamage` 是目标实际接收的伤害，目标拒绝伤害时为 0。适合命中特效及浮字。 |
| EnemyCharacter | `OnEnemyDied()`（已有） | 普通死亡已将生命置 0、进入 Dead、停止移动并关闭碰撞后；在尸体延迟清理前调用。读档恢复死亡不会再次调用。 |
| EnemyNest | `OnPlayerRangeChanged(bNowInRange)` | 玩家进入或离开窝点仇恨范围、或正常摧毁窝点导致范围失效时。可切换窝点警戒表现。读档恢复销毁状态静默执行。 |
| EnemyNest | `OnEnemySpawned(SpawnedEnemy)` | 敌人已成功生成、Owner 已设为窝点、已计入活动数量之后。可对这个现有实例设置表现；不要再 Spawn 同一只敌人。 |
| EnemyNest | `OnNestDestroyed()`（已有） | 普通战斗将窝点生命降到 0，窝点已隐藏、关闭碰撞与生成计时后。读档恢复销毁状态不会再次调用。 |
| AlcoholArea | `OnAreaActivated()` | 已设置区域寿命、周期伤害计时和默认特效/音效之后，仅一次。可以启动附加表现。 |
| AlcoholArea | `OnTargetDamaged(Target, ActualDamage)` | 本轮对某个目标成功造成正伤害后；对应减速及变身累积已处理完毕。多目标或多次持续伤害会各自通知。 |
| AlcoholArea | `OnAreaTickCompleted(DamagedTargets, TotalDamage)` | 一次周期伤害扫描处理完所有目标后，仅一次；无成功伤害时参数为 0、0。它不是第二个伤害执行入口。 |
| AlcoholProjectile | `OnProjectileLaunched(RequestedTarget, InitialVelocity)` | 初速度已赋予 ProjectileMovement 并启用飞行后。RequestedTarget 是原请求位置，实际轨迹仍会受最大距离约束。 |
| AlcoholProjectile | `OnProjectileBurst(SpawnedArea, BurstLocation)` | 地面位置已求出、默认爆开特效/音效已播放、持续伤害区域已生成后。SpawnedArea 可能为空，使用前先 IsValid。事件返回后瓶子立刻销毁，因此不要在瓶子自身上接 Delay；后续表现应放在 Area 或独立特效中。 |

资源提交、窝点生成、区域单次结算都包含重入保护，防止同一通知调用栈递归触发原动作。不同时间再次手动调用仍然可能造成额外动作，所以蓝图应遵守上表的职责。

## 两个可直接照做的例子

### 让资源点在指定状态下暂停采集

1. 在资源蓝图添加 `bHarvestEnabled` 布尔变量，勾选 Instance Editable，默认 true。
2. 重写 `CanHarvest`，直接返回 `bHarvestEnabled`。
3. 继续使用原有 F 采集流程；不要另建计时器添加物品。
4. 可以用 `OnHarvestCommitted` 播放一次闪光，用 `OnAvailabilityChanged` 更新可采集提示。

### 给敌人警觉和死亡反馈

1. 在 `BP_DWEnemy` 的 Event Graph 添加 `OnStateChanged`。
2. 对 `NewState` 使用 Switch：Chase 显示警觉表现，Attack 切换攻击表现，Patrol 恢复普通表现。
3. 死亡特效放在 `OnEnemyDied`，只播放表现；现有生命值、碰撞和保存状态由 C++ 处理。
4. 需要限制发现条件时重写 `CanDetectTarget`，先调用父实现，再结合附加条件。不要直接在图中重复每帧调用 ApplyDamage。

## 参数、读档和验证边界

- 场景中要保存消耗或死亡状态的资源、窝点、敌人应有唯一的 `PersistentId`。有 ID 的死亡敌人会保留隐藏实例供保存枚举；窝点生成且没有 ID 的临时敌人会按死亡延迟清理。
- 读取存档不会覆盖已保存的敌人/窝点生命值，也不会再次触发其死亡奖励事件。蓝图 BeginPlay 中不要无条件把 Health 设置回 MaxHealth。
- 伤害区域的 `bGrantTransformationOnEveryDamageTick` 默认 true：每次有效伤害都累积变身；false 时同一瓶产生的区域仅首次有效伤害累积一次。`OnTargetDamaged` 在两种设置下仍会对每次有效伤害通知。
- 保留现有 `AttackSound`、`DeathSound`、`TrailVFX`、`ImpactVFX`、`AreaVFX` 等可编辑插槽。填入插槽后原逻辑会自动播放，在通知里又播放同一效果会重复。
- 本指南描述已落地的接口设计。具体 C++ 构建、蓝图重编译及游戏运行验收以本次交付测试报告为准；单有事件节点并不代表已制作最终美术或动画。

源码位置：`Source/GDATtest/Gameplay/DWResourceNode.*`、`DWEnemyCharacter.*`、`DWEnemyNest.*`、`DWAlcoholArea.*`、`DWAlcoholProjectile.*`。

## 玩家：规则与成功通知

玩家编辑入口是 `/Game/DoughWorld/Maps/Gameplay/Blueprints/BP_DWTopDownCharacter`，原生类为 `ADWPlayerCharacter`。本章只扩展新玩法玩家，不要求改动旧 TopDown 蓝图或程序组角色。

### 额外许可规则

在玩家蓝图的 **Overrides / 重写** 中选择以下纯函数。它们的原生实现均返回 true，含义是“允许继续通过这一条额外条件”。即使蓝图返回 true，C++ 中的死亡、冷却、已在冲刺、库存、满变身值等原有守卫仍然生效。

| 规则 | 参数 / 返回 | 生效位置 |
|---|---|---|
| `CanSprint` | 无参数，返回 bool | 决定能否使用 Shift 疾跑倍率及累积新的疾跑消耗 / 产出时间。已有但因满包延迟交付的酒精不会被此规则清除。 |
| `CanDash` | 无参数，返回 bool | `PerformDash()` 在开始短冲刺前检查。返回 false 时不开始冲刺、不触发成功通知。 |
| `CanThrowAlcohol` | `TargetLocation`，返回 bool | 玩家检查冷却和现有酒精数量后，生成瓶子前检查。参数是调用方请求的世界目标，后续仍受最大距离限制。 |
| `CanEnterYeastForm` | 无参数，返回 bool | 玩家未死亡、尚非酵母形态且变身值已满后，再执行这一额外判断。 |

规则可能在一帧中被查询多次。只读取状态并返回结果，不在规则内扣血、加物品、移动角色或播放一次性奖励。

例如要加入“特殊区域禁止疾跑”，在玩家蓝图增加 `bSprintAllowedInCurrentZone`，默认 true；重写 `CanSprint` 并返回该值，由区域进入 / 离开事件更新这个变量即可。现有移动输入、生命扣除和累计产出仍由原流程处理。

外部蓝图应调用 `PerformDash()`、`ThrowAlcoholAt()`、`TryTransform()` 等新玩家入口。直接调用继承的底层 `StartForwardRoll()`，不会经过新玩家的 `CanDash` 和 `OnDashStarted`，不适合作为新的玩法触发入口。

### 成功通知

在 Event Graph 中右键搜索下列事件。通知发生时，对应动作的核心状态已经提交；用它们连接额外表现或任务统计，不要再次扣血、扣物品或发放同一批产物。

| 事件 | 参数 | 通知时核心状态 |
|---|---|---|
| `OnDashStarted` | 无 | 底层短冲刺已成功启动，采集已中断，占位拖尾与可选 Niagara 已启动。被冷却拒绝的请求不通知。 |
| `OnSprintAlcoholProduced` | `Amount` | 对应数量的酒精已完整入包，该周期已从累计秒数扣除。满包时不触发，腾出空间实际入包后才触发；一次补交多个周期会逐批通知。 |
| `OnResourceHarvested` | `Resource`、`ItemId`、`Amount` | 物品已入包，资源消耗已提交；如果是酵母，对应变身增值也已处理。Resource 可能因其他扩展被销毁而为空，使用前 IsValid。 |
| `OnFormChanged` | `bNowYeastForm` | 正常主动变身为 true，变身值耗尽恢复面团为 false；材质状态已更新。主动变身的内置晃动与可选音效也已执行。 |
| `OnAlcoholThrown` | `Projectile`、`TargetLocation`、`AlcoholSpent` | 已扣除本次配置的酒精数量、启动瓶子飞行和投掷冷却。TargetLocation 是玩家最大距离处理后的目标；Projectile 使用前 IsValid。 |
| `OnInventoryItemUsed` | `ItemId`、`HealthRestored`、`TransformationGained` | 已消耗一个可用物品，并应用治疗 / 变身值变化。后两个参数是实际增加的点数，包含上限裁切，并非配置百分比。 |
| `OnRecipeCrafted` | `RecipeId` | 原料扣除和全部产物入包已作为一个事务提交。失败不通知。 |
| `OnPlayerDied` | 无 | 本次正常死亡已停止移动、关闭玩家行动，并显示死亡界面 / 播放已有死亡表现。同一死亡只通知一次。 |

资源本身也有 `OnHarvestCommitted`；若同一特效同时接在资源事件和玩家 `OnResourceHarvested` 上，会显示两次。应根据特效挂在资源还是玩家上，选择适合的一处接入。

内置声音、材质染色和 Niagara 插槽仍然有效。如果插槽已经播放某个效果，就不要在新通知里再次播放同一个效果。需要全新表现时可以清空对应插槽，统一由事件实现。

### 重入与读档约定

玩家的计时、采集、短冲刺、投掷、使用和合成事务共用调用栈保护。在成功通知或背包 `OnChanged` 回调中立刻再次调用这些玩家动作，会被拒绝，以免一次回调递归产生多次消耗或奖励。需要串联新的独立动作时，在事件返回之后安排下一次调用，并自行明确其成本和触发条件。

存档恢复不重放 `OnSprintAlcoholProduced`、`OnResourceHarvested`、`OnFormChanged`、`OnInventoryItemUsed`、`OnRecipeCrafted` 或 `OnPlayerDied`。生命、库存和形态仍会恢复，材质也会刷新；背包 `OnChanged` 可以通知界面重新绘制，但不能据此给奖励。

如果自定义 HUD 或人物特效需要在读档后恢复显示，在自己的初始化 / 刷新函数里读取 `IsYeastForm()`、`GetHealth()`、`GetTransformation()` 与背包内容，不要通过手动调用成功事件来重新发奖。

### 标题暂停时的摄像机初始化

新增玩家参数 `CameraDistance`，默认 `1800` 厘米，可在玩家蓝图 Class Defaults → `DoughWorld | Camera` 调整。它控制 SpringArm 长度；`CameraDragSensitivity`、`MinCameraPitch`、`MaxCameraPitch` 继续控制拖动灵敏度与俯仰范围。

玩家 `BeginPlay` 在读取初始摄像机角度后，立即应用限制后的旋转和长度，并在存档位置恢复后刷新一次 SpringArm。这样标题界面即使在第一帧暂停世界，也无需等待普通 Tick 才能得到正确初始视角。

本章改动仅位于 `DWPlayerCharacter.h/.cpp`。蓝图事件的反射编译、已有蓝图重新编译以及游戏中的效果验证，仍需纳入本轮后续构建和 PIE 检查。
