## 3. 启动、GameInstance 与单图流程

同一张 `L_DoughWorld_GameplayPrototype` 同时承载标题和实际游玩。是否进入游戏由 `UDWGameInstance::HasActiveSlot()` 判断，不能靠“当前地图是不是标题地图”判断。

1. 启动时 `ActiveSlot == INDEX_NONE`：显示标题，等待选择存档。
2. 新建：`NewGame(SlotIndex, Name)` 检查空槽，写入初始状态，设置活动槽及 `PendingSave`，再打开玩法地图。
3. 读档：`LoadGameSlot(SlotIndex)` 校验存档，设置活动槽和待恢复对象，再打开同图。
4. 新玩家 `BeginPlay` 初始化配置和背包后，调用 `GI->ApplyPendingSave(this)`。
5. 返回标题：`ReturnToTitle()` 清除活动槽和待恢复对象，重新打开同图。此函数**不自动保存**；“保存并返回”应先检查 `SaveCurrentGame()` 返回成功。

项目设置中应配置以下关系；本轮执行者须在资源生成后核验最终配置：

```ini
[/Script/EngineSettings.GameMapsSettings]
GameInstanceClass=/Script/GDATtest.DWGameInstance
GameDefaultMap=/Game/DoughWorld/Maps/Gameplay/Levels/L_DoughWorld_GameplayPrototype
```

玩法地图的 World Settings → GameMode Override 指向 `BP_DWTopDownGameMode`。其 `DefaultPawnClass`、`PlayerControllerClass`、`HUDClass` 分别指向上述新玩家、控制器、HUD 蓝图。编辑器默认打开哪张图可以单独设置；不要通过改写旧地图的 GameMode Override 来接入新流程。

`DA_DoughWorldGameplay.GameplayMap` 与 `MainMenuMap` 当前均填同一新地图路径。`UDWGameInstance.SoftConfigPath` 默认指向 `/Game/DoughWorld/Maps/Gameplay/Data/DA_DoughWorldGameplay.DA_DoughWorldGameplay`；资源缺失时会使用原生默认配置，便于诊断，但正式交付须确认真实 DataAsset 引用存在。

## 4. 数据结构、优先级与配表方法

### 4.1 哪一层负责哪些配置

| 修改目标 | 应编辑的位置 |
|---|---|
| 玩家生命、基础速度、疾跑成本、变身规则、背包容量 | `DA_DoughWorldGameplay` |
| 物品名、图标、使用效果 | `DT_DWItems` |
| 合成配方 | `DT_DWRecipes` |
| 所有同类资源点或敌人的默认参数 | 对应 Actor 蓝图的 Class Defaults |
| 地图中某一个资源总量、窝点范围或持久化 ID | 该 Actor 实例的 Details |
| 玩家动画、冲刺表现、摄像机与投掷类 | `BP_DWTopDownCharacter` |
| 酒精瓶飞行和毒池伤害 | Projectile / Area 两个独立蓝图 |

`GetConfig()` 首次取得 DataAsset 后调用 `RefreshDefinitionsFromTables()`。类型和内容有效的 DataTable 会覆盖配置中的 `Items` / `Recipes` 数组；无表或表错误时才使用数组回退。因此已经绑定表时，应修改表，不要同时维护另一套数组数值。

配置在 GameInstance 中缓存。修改表后保存资源并重新开始 PIE，或由程序显式调用 `RefreshDefinitionsFromTables()`。重新开始 PIE 更适合同时修改物品 ID、槽位容量等结构性配置的情况。玩家 `BeginPlay` 使用 GameInstance 的统一配置；不要假设单独改玩家蓝图的 `GameplayConfig` 能覆盖 GameInstance。

### 4.2 背包槽位 `FDWItemStack`

| 字段 | 类型 | 含义 |
|---|---|---|
| `ItemId` | `FName` | 稳定的物品逻辑 ID |
| `Quantity` | `int32` | 此槽数量；运行时有效槽必须大于 0 且不超过堆叠上限 |

槽位数组只保存已占用槽；空格子的绘制由 UI 补齐。删除空堆叠后数组会压缩，UI 不应把某个数组索引当作永不变化的物品唯一 ID。

### 4.3 物品表 `FDWItemDefinition : FTableRowBase`

| 字段 | 类型 | 编辑用途 |
|---|---|---|
| `ItemId` | `FName` | 推荐与 DataTable Row Name 相同，不能重复 |
| `DisplayName` | `FText` | 可独立修改的显示名称 |
| `Icon` | `UTexture2D*` | 每种物品独立的美术图标引用，当前可留空 |
| `IconColor` | `FLinearColor` | 图标缺失时的占位颜色 |
| `bUsable` | `bool` | 是否允许在背包中使用 |
| `HealAmount` | `float` | 每次使用回复的生命点数 |
| `TransformationGainPercent` | `float` | 每次使用增加的变身上限百分比，填 `1` 表示 `1%` |

当前五个稳定 ID 为 `Flour`、`Water`、`Dough`、`Yeast`、`Alcohol`。默认仅 `Dough` 可使用，回复 `10` 点生命，使用增加变身值为 `0`；其他四项 `bUsable=false`。酵母“采集时增加变身值”由玩家采集流程负责，与物品“使用时增加变身值”是独立接口。

新增物品时，在 `DT_DWItems` 增加行，填写唯一 `ItemId`、名称和图标；需要采集时，将资源 Actor 的 `ItemId` 填成同一值；需要制作时在配方引用此值。已有存档使用 `ItemId`，因此仅修改显示名称可以兼容旧存档；改 ID 或删除物品需要编写存档迁移，不能用改名后静默丢物品的方式处理。

### 4.4 配方表 `FDWRecipeDefinition : FTableRowBase`

| 字段 | 类型 | 编辑用途 |
|---|---|---|
| `RecipeId` | `FName` | 唯一的配方逻辑 ID |
| `DisplayName` | `FText` | 制作页名称 |
| `Inputs` | `TArray<FDWItemStack>` | 原料 ID 与数量，可配置多项 |
| `Outputs` | `TArray<FDWItemStack>` | 产物 ID 与数量，可配置多项 |
| `bRequiresYeast` | `bool` | 是否要求当前处于酵母形态 |

| 已确认配方 ID | 原料 | 产物 | 形态条件 |
|---|---|---|---|
| `CraftDough` | `Flour × 2`、`Water × 2` | `Dough × 1` | `bRequiresYeast=true` |
| `CraftAlcohol` | `Dough × 3`、`Yeast × 2` | `Alcohol × 1` | `bRequiresYeast=true` |

在 DataTable 编辑器中展开 `Inputs` / `Outputs` 修改数组元素。数量必须为正，所有 ItemId 都必须存在。当前不接受空原料或空产物配方；同一种原料出现多行时会累计需求。制作会先在临时背包扣除原料，再检查所有产物能否进入释放出的槽位，全部成功后一次提交；失败不扣料。

| `ADWDoughResourceNode` / `_Dough` | Dough | 3 s | 3 | 否 | 3 / 原型实例 30 |
| `ADWFlourResourceNode` / `_Flour` | Flour | 3 s | 2 | 否 | 20 / 原型实例 60 |

松开 F、走出范围、切换到另一个资源点，会清除本次采集进度。这一计时与可跨次累计的疾跑产酒精计时独立。

| Nest | `SpawnInterval` | 10 s |
| Nest | `SpawnRadius` | 220 cm |
| Nest | `MaxAliveEnemies` | 0，表示不限制活敌数量；可调整 |
| Nest | `EnemyClass` | 原型绑定 `BP_DWEnemy` |
| Projectile | `FlightTime` | 0.65 s |

| Projectile | `AreaClass` | 原型绑定 `BP_DWAlcoholArea` |
| Area | `Duration` | 5 s |
| Area | `DamageInterval` | 0.3 s |

窝点在玩家进入范围后累计刷新；离开范围会清空当前窝点刷新计时。检测球、仇恨球和采集球在编辑器可视，游戏中隐藏。敌人有 `Patrol`、`Chase`、`Attack`、`Dead` 四个状态；默认需要视线才能发现和攻击玩家。无有效 NavMesh 时存在 CharacterMovement 直向移动回退，但正式布局仍应覆盖有效导航数据。

毒池首次周期伤害在 `DamageInterval` 后发生，池到期停止伤害。毒池可以伤害敌人和窝点；减速只作用于敌人。多个减速重叠时使用仍未过期效果中的最强值，而不是重复相乘；伤害池之间可以分别产生伤害。

`bGrantTransformationOnEveryDamageTick=true` 时，每次对每个目标造成正数伤害会调用一次 `NotifyAlcoholHit()`。例如同一跳伤害命中两个目标，默认可以累计两次 `AttackGainPercent`；设为 false 时，每个毒池实例最多触发一次增值。此项须纳入数值平衡验收。

表现接口：敌人 `AttackSound`、`DeathSound`、`OnEnemyAttack(Victim)`、`OnEnemyDied()`；窝点 `OnNestDestroyed()`；投射物 `TrailVFX`、`ImpactVFX`、`ImpactSound`；伤害区 `AreaVFX`、`AreaSound`。加载“已死亡”状态走静默恢复，不重新触发死亡奖励事件。

## 6. 程序调用约定

### 6.1 背包与采集

| API | 调用规则 |
|---|---|
| `InitializeInventory(Config)` | 玩家初始化时绑定统一配置 |
| `CountItem(ItemId)` | 获取背包中该物品合计数量 |
| `TryAddItem(ItemId, Quantity)` | 全量成功才返回 true；满包、未知物品、非法数量不会部分加入 |
| `TryRemoveItem(ItemId, Quantity)` | 数量足够才整体扣除 |
| `GetSlots()` | C++ 只读引用；不要自行写入数组 |
| `GetInventorySlots()` | 蓝图可获取的槽位数组副本 |
| `OnChanged` | 成功提交库存变更后广播，适合刷新表现 |
| `SetSlots(Slots)` / `AreSlotsValid(Slots)` | 加载使用；拒绝未知 ID、负数、超堆叠及超容量，不截断丢物品 |

资源必须先入包成功，再提交采集消耗：

```cpp
if (Inventory->TryAddItem(Node->ItemId, Amount))
{
    Node->CommitHarvest(Amount);
    // 此时再触发酵母增值、采集音效或任务统计。
}
```

需要扩展任务计数时，连接 `ADWResourceNode::OnHarvestCommitted(ActualAmount)`。不要先扣资源后尝试入包，也不要另建一个独立的 `Wood` 计数再试图和背包同步。

### 6.2 使用、合成和战斗

界面或交互调用玩家 `UseInventoryItem(SlotIndex)`，由玩家检查是否存在有效用途，再通过 `ConsumeOneAtSlot` 消耗物品并施加效果。外部 UI 不应单独调用 `ConsumeOneAtSlot` 然后遗漏治疗；生命已满且没有其他有效效果时不消耗物品。

配方预览可调用 `Inventory->CanCraft(RecipeId, Player->IsYeastForm())`。正式执行建议调用 `Player->CraftRecipe(RecipeId)`，统一完成死亡状态校验、库存事务和结果提示。不要把 `CanCraft` 当作一次永久授权；真正的 `TryCraft` 会再次验证当前库存和形态。

投掷入口为 `Player->ThrowAlcoholAt(TargetWorldLocation)`，生成酒精瓶后扣除酒精，成功才进入冷却。瓶子通过 `LaunchAtTarget` 飞行，碰撞 / 落地后生成 Area。伤害使用 UE `ApplyDamage` / `TakeDamage` 通道；修改特效时保留这条逻辑链。当前没有独立近战攻击。

### 6.3 存档 API

| API | 返回值 / 约束 |
|---|---|
| `GetConfig()` | 统一配置对象 |
| `GetSlotSummaries()` | 固定返回 3 项；每项含 `SlotIndex`、`bExists`、名称、时间、地图 |
| `GetActiveSlot()` / `HasActiveSlot()` | 内部索引为 0、1、2；界面显示为槽 1、2、3 |
| `NewGame(SlotIndex, Name)` | 仅空槽；不隐式覆盖已有档 |
| `LoadGameSlot(SlotIndex)` | 验证版本、地图、数值与物品后才切图 |
| `DeleteGameSlot(SlotIndex)` | UI 确认后调用，越界不执行；若删除活动槽会清活动状态 |
| `SaveCurrentGame()` | 必须是活动存档、新玩法地图、有效且存活的玩家 |
| `ReturnToTitle()` | 导航到标题，不隐式保存 |
| `ApplyPendingSave(Player)` | 玩家 `BeginPlay` 中应用跨关卡保留的数据 |
| `LastSaveError` | 失败原因，可直接显示给用户 |

死亡不能覆盖上次存档。新槽的 `bHasPlayerTransform=false`，使用地图的 PlayerStart；第一次实际保存后改为 true，之后恢复真实玩家位置。

## 7. 存档内容、持久化 ID 与当前边界

当前 `UDWSaveGame::CurrentVersion = 1`，三个槽文件名为 `DoughWorld_Final_Slot_1`、`_2`、`_3`。标准 UE SaveGame 写入项目 Saved 路径下的 `SaveGames` 目录；编辑器工程通常为 `E:/Unreal Project/GDATtest/Saved/SaveGames`。存档不是 Content 资产，导入关卡资源不会自动带走玩家存档。

| 保存字段 | 含义 |
|---|---|
| `Version`、`DisplayName`、`Timestamp`、`MapPackage` | 版本、显示名、UTC 时间和地图长包路径 |
| `PlayerTransform`、`bHasPlayerTransform` | 玩家位置、旋转、缩放及是否应用 |
| `Health`、`Transformation`、`bYeastForm` | 玩家生命、变身值和形态 |
| `SprintAlcoholElapsed` | 疾跑产酒精剩余累计时间，包括满包延迟交付的已完成进度 |
| `TransformationDecayElapsed` | 自然衰减周期的未完成时间 |
| `Inventory` | 物品 ID 与每槽数量 |
| `WorldActors` | 带稳定 ID 的资源、敌人、窝点生命 / 剩余量与销毁状态 |

### 7.1 如何填写 PersistentId

在已摆放的资源、敌人和窝点实例 Details 中填写 `PersistentId`。命名示例：`Prototype_Water`、`Prototype_Yeast`、`Prototype_Enemy_01`、`Prototype_Nest_01`。同一类型的不同物件不能共用 ID；复制物件后必须另起 ID。

保存键会自动添加类型前缀：`Resource:<PersistentId>`、`Enemy:<PersistentId>`、`Nest:<PersistentId>`。`Resource` 行的 `FDWPersistedActorState.Health` 字段暂存剩余资源数量，载入时还原为整数；Enemy / Nest 行则存生命值。

保存时会拒绝空保存键、重复完整保存键、非法数值。空 `PersistentId` 的 Actor 直接不进入世界状态存档。不要用编辑器 Actor Label 或随机生成名字代替手工稳定 ID。

资源耗尽和有 ID 的敌人 / 窝点死亡后，会保留可查询的逻辑 Actor，通过隐藏 / 禁用碰撞等方式表示结束，以便再次保存其状态。加载已有死亡状态不触发新的奖励事件。Enemy / Nest 另有初始化保护，确保先恢复生命再执行 `BeginPlay` 时，不被默认满血覆盖。

### 7.2 当前明确不保存的状态

- 窝点在运行时生成且没有 `PersistentId` 的敌人；重新载入后由窝点继续正常刷新。
- 动态敌人的数量、精确位置、当前巡逻路线、仇恨目标和攻击冷却。
- 酒精瓶的飞行中状态、场上毒池及其剩余寿命、敌人临时减速。
- 窝点当前 10 秒刷新周期的部分进度；重新载入重新计时。
- 一次正在按 F 的采集部分进度、摄像机当前拖拽角度和动画当前播放帧。

因此本轮存档是“玩家成长 / 背包 + 关键已摆放物件状态”，不是战斗场景的逐帧快照。后续如果需要动态敌人全量恢复，应扩展 `WorldActors`，增加 Actor 类型 / 蓝图软路径、变换、动态生成 ID 与生成归属，统一版本迁移后再启用。

修改 `MaxStackSize`、`MaxInventorySlots` 或删除 ItemId 后，旧档可能无法满足新的数据约束。当前策略是拒绝加载并保留原档；不存在自动截断。正式发布时应通过存档版本转换重新分配堆叠或给出迁移补偿。

## 8. 原 TopDown 与程序组成果保留策略

新 `BP_DWTopDownCharacter` 从旧 TopDown 玩家蓝图复制并派生到 `ADWPlayerCharacter`，继续利用 `ATopDownActionCharacter` 的短距离行动实现。新的 `ADWPlayerController` 负责本轮按键，程序组角色控制器与原角色不接入。

共享 `TopDownActionCharacter` 只增加了 `bBindDefaultActionKeys` 和 `bUseSomersaultVisual` 两个开关；其原生默认均为 true，让旧蓝图保持原输入和翻身表现。新派生玩家明确设 false，并设置 `JumpMaxCount=0` / 禁止跳跃，以空格短冲刺代替跳跃。旧地图、旧角色蓝图和原程序组 UI 不需要为新关卡改写。

项目使用同一个 `GDATtest` 模块，所以公共父类的后续改动仍可能影响旧图。以后修改冲刺碰撞、冷却或父类生命周期时，除了新图测试，也应在旧图做针对性回归；不要将“资源未覆写”误解为“共享 C++ 完全隔离”。
