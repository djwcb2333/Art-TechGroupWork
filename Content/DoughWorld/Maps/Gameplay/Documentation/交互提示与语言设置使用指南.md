# 交互提示与语言设置使用指南

版本：2026-09-16，按本轮已实现接口与现有验证记录更新。

本轮把资源交互提示放到物体上方，配上弹出动效和短促的老式键盘按键声；游戏界面统一使用支持中文、英文和数字的手写风格字体，并在设置中加入中英文切换。本文说明操作入口和编辑方法。最终 C++ 编译、变身与音频专项 PIE 检查、重启后的语言偏好检查及 48 项交互回归均已通过；验收范围与证据见第 11 节和《本轮交付与验证.md》。

## 1. 在游戏中怎样使用

1. 打开玩法测试地图 `Content/DoughWorld/Maps/Gameplay/Levels/L_DoughWorld_GameplayPrototype`，运行后开始或加载一份游戏。
2. 靠近水、酵母、面团或面粉资源。成为当前采集目标的资源上方会显示资源名、`F` 按键和“长按采集”。提示出现时播放一次键盘按键声。
3. 按住 `F` 采集。进度条显示当前这一轮采集进度，物品发放和数量由原有采集系统决定；文字显示本身不另发物品。
4. 离开目标或切换目标，提示退出。打开阻止角色操作的菜单、暂停或死亡时，提示立即隐藏。
5. 在开始界面进入“设置”，或游戏中按 `Esc` 打开暂停菜单后进入“设置”。在“语言 / Language”中选择“简体中文”或“English”。选择后立即切换并保存语言，不必再点“应用设置”。分辨率等图像设置仍按原有“应用设置”按钮处理。

同一目标持续显示时不会每帧重复弹出或反复播放声音。采集进度变化也不会重启动效。短时间内多个提示相继出现时，共享声音冷却会抑制连续响声。

## 3. 中英文设置会怎样保存

语言属于玩家的本地偏好，独立于三份游戏进度存档。新建、删除或切换游戏存档，不应改变已选择的语言。程序下一次初始化游戏实例时会读取上一次保存的偏好。

设置保存在当前运行项目的：

```text
Saved/Config/DoughWorldPreferences.ini
```

当前编辑器工程对应：

```text
E:/Unreal Project/GDATtest/Saved/Config/DoughWorldPreferences.ini
```

其中 `[Language]` 下的 `Code=en` 表示英文，`Code=zh-Hans` 表示简体中文。缺少偏好文件时默认简体中文。打包运行后的保存位置由 UE 的运行环境决定，不要求玩家手动编辑这个文件。

这套切换只影响本游戏的文本，不改变 UE 编辑器界面语言。玩家自己输入的存档名属于用户内容，会保留原文。

## 4. 修改整个游戏的字体

本轮组合字体使用站酷快乐体显示中文、Lilita One 显示英文与数字。二者的原始字体和 OFL 授权文件均保存在 `SourceAssets/Fonts`；具体说明见该目录的《字体选型与授权说明.md》。

编辑时分成两个入口：

| 修改范围 | 操作 |
|---|---|
| 主界面、状态文字、背包、配方、存档、设置及下拉选项等游戏 UI | 打开 `BP_DWGameplayHUD`，进入“类默认值”，修改 `Game UI Font`。默认使用 `F_DWHandDrawn`。 |
| 物体上方交互提示 | 打开 `DA_DWInteractionPromptStyle`，修改 `Title Font`、`Key Font` 和各字号。 |

需要同时保留中英文时，主 UI 字体和提示的 `Title Font` 应选择中英组合字体，或另一个确实覆盖中英文的组合字体。仅选英文单字体可能让中文显示为方框。按键目前主要是 `F`，`Key Font` 可以单独使用英文字体。

已有四个主 UI Widget Blueprint 的 Designer 文本和下拉控件也会设置组合字体。运行时会按 HUD 字体再次应用，因此单独改某个 TextBlock 的字体后发现运行时恢复，是运行时总入口覆盖造成的。希望改全部字体时应优先改 HUD 和提示 Style；各界面的字号与布局仍在其 Designer 中调整。

## 5. 调整提示样式

打开 `DA_DWInteractionPromptStyle`。下面的默认值来自当前 C++ 初值，已保存资产可能另有配置，以 UE 详情面板显示为准。

| 参数 | 初值 | 调整效果 |
|---|---:|---|
| `Title Font` / `Key Font` | 由样式资产指定 | 资源名与动作文字字体 / 按键字体 |
| `Title Font Size` | 32 | 资源名字号 |
| `Action Font Size` | 20 | “长按采集”等动作文字字号 |
| `Key Font Size` | 23 | 按键文字字号 |
| `Outline Size` | 2 | 资源名与动作文字描边粗细 |
| `Text Color` / `Outline Color` | 奶油色 / 深棕色 | 提示文字和描边颜色；按键文字使用深色 |
| `Keycap Color` | 浅米色 | 按键底板颜色 |
| `Progress Color` | 浅绿色 | 采集进度颜色 |
| `Appear Duration` | 0.42 秒 | 弹出并稳定的时间 |
| `Disappear Duration` | 0.16 秒 | 离开目标时退出的时间 |
| `Float Distance` | 24 像素 | 进入动效的位移量，不是物体上方的空间高度 |
| `Initial Scale` | 0.55 | 弹出起始缩放 |
| `Overshoot Amount` | 0.16 | 弹出后稍微放大再回落的幅度 |
| `Wobble Degrees` | 4 度 | 弹出摆动幅度 |
| `Use Native Motion` | 开启 | 使用现成的弹出、摆动和退出动效 |
| `Appear Sound` | 由样式资产指定 | 提示出现时的声音，可换 Sound Wave 或 Sound Cue |
| `Sound Volume` | 0.65 | 提示声音倍率 |
| `Sound Pitch` | 1.0 | 声音播放音高/速度倍率 |
| `Sound Cooldown` | 0.65 秒 | 两次提示声之间的最短冷却，包含同一世界共享限制 |

想让提示安静些，先减小 `Sound Volume`；想完全取消默认提示音，可清空 `Appear Sound`。要让单个 Actor 静音，关闭它的提示组件上的 `Play Appear Sound`，无需改整个共享 Style。

想让某一类物体使用不同风格：复制这个 Style 资产、改参数，再把副本赋给该物体的提示组件 `Style`。改原共享资产会影响使用它的其他物体。

## 6. 直接在 Designer 改提示布局

`WBP_DWInteractionPrompt` 是可打开、可保存的真实 Widget Blueprint。进入 Designer 后可以改排版、间距、底板和装饰图形。

以下控件由 C++ 按名字绑定，请保留名字与控件类型：

| 控件名 | 类型 | 用途 |
|---|---|---|
| `PromptVisual` | Size Box | 提示内容的动效容器 |
| `PromptTitle` | Text Block | 资源名/物体名 |
| `ActionText` | Text Block | 动作提示 |
| `KeyText` | Text Block | 按键文字 |
| `Keycap` | Border | 按键底板 |
| `HarvestProgress` | Progress Bar | 采集进度 |

运行时会写入资源名、动作、按键和进度，并按 Style 应用字体、字号、颜色；这些内容应通过数据和 Style 修改。不要仅在 Designer 中把预览文字改成“水”，然后期望所有资源都沿用这段固定文字。

如要使用自己制作的提示 Widget Blueprint，父类必须为 `DWInteractionPromptWidget`，并保留以上绑定。把它填入组件的 `Widget Class`。留空时组件会加载默认 `WBP_DWInteractionPrompt`。

蓝图中可以使用这些通知：

- `On Prompt Appeared`：目标从隐藏切换为显示时调用一次，适合额外的装饰动画。
- `On Prompt Disappeared`：目标切换为隐藏时调用一次。
- `On Progress Changed`：采集进度发生变化时调用，参数为 0 到 1。

使用自制 UMG 动画时可关闭 `Use Native Motion`，并在这些通知中播放动画。当前原生逻辑仍负责整个 Widget 的显示/隐藏透明度：不要在自制动画中同时控制 Widget 根透明度。优先动画化 `PromptVisual` 内的装饰子控件。关闭原生动效时退出会直接隐藏；若需要完整自定义退出动画，需要程序进一步开放退出完成回调，不能只通过 Designer 保证实现。

## 7. 给新的 Actor 加提示

以一个新建的箱子或门为例：

1. 打开该 Actor 蓝图，在“组件”面板点击“添加”，搜索 `DWInteractionPromptComponent` 或 `DW Interaction Prompt`。
2. 将提示组件挂到现有的 `DefaultSceneRoot` 或模型组件下面。不要把提示组件设为 Actor 的根组件。
3. 在详情面板填写中文标题 `Generic Prompt Title` 和动作 `Generic Prompt Action`。
4. 填写对应英文 `Generic English Prompt Title` 和 `Generic English Action`。例如“木箱 / Crate”“打开 / Open”。英文为空时会保留该 Actor 的原始中文字段。
5. 在 `Generic Prompt Key` 填提示按键，例如 `F`。
6. 调整 `Generic Detection Radius` 控制出现距离，默认 220 厘米；`Height Tolerance` 默认 300 厘米，用来限制上下楼层的高度差。
7. 调整 `World Offset` 的 Z 把提示放在模型上方，默认 145 厘米。这个偏移按世界空间计算，不会随模型缩放一同放大。
8. 需要特殊样式时指定 `Style`；否则沿用默认样式。需要特殊版式时指定 `Widget Class`；否则沿用默认提示 WBP。
9. 编译、保存蓝图，放入测试地图，在游戏会话开始后靠近观察。

**给普通 Actor 加这个组件，只会增加靠近时的提示显示与声音，不会自动获得 F 输入、开门、采集、发物品或存档逻辑。** `Generic Prompt Key` 也是显示字段，修改它不会更换输入绑定。实际动作需要接到玩家或项目现有的交互实现中。

组件提供 `Set Prompt Enabled` 用于在蓝图中启用/关闭提示，以及 `On Prompt Shown`、`On Prompt Hidden` 通知。通知发生在可见性切换时，不能拿 `On Prompt Shown` 当成“玩家已经按下 F”的事件。

## 8. 已有资源不需要再加组件

`DWResourceNode` 已在原生构造中创建名为 `InteractionPrompt` 的组件。原来的水、酵母、面团和面粉蓝图会通过继承自动带上它。直接在现有资源上改这个继承组件即可，手动再添加一个会产生重复提示。

资源和普通 Actor 的判定入口有所不同：

| 物体类型 | 应修改的范围 | 显示依据 |
|---|---|---|
| 已有 `DWResourceNode` 资源及其子类 | 资源 Actor 的 `Interaction Radius` | 玩家当前实际采集目标；提示和 F 采集目标一致 |
| 普通 Actor 加提示组件 | 组件的 `Generic Detection Radius` | 本地玩家与物体的水平距离 |

资源提示标题来自物品表；`Generic Prompt Title` 不覆盖资源名。资源进度读取玩家的真实采集进度，采集间隔、单次数量、无限/有限资源等继续在资源 Actor 的原有参数上修改。

旧的底部交互文字兼容开关位于 `BP_DWGameplayHUD → Use Legacy Interaction Prompt`，默认关闭。使用物体上方提示时保持关闭即可避免新旧提示同时出现。

## 9. 给新物品和配方填写中英文

打开 `DT_DWItems`，每一行中：

- `ItemId`：程序识别用的固定 ID，保留英文命名，不要为了切换语言而修改。
- `DisplayName`：中文显示名称。
- `EnglishDisplayName`：英文显示名称。

现有物品对应如下：

| ItemId | DisplayName | EnglishDisplayName |
|---|---|---|
| `Flour` | 面粉 | Flour |
| `Water` | 水 | Water |
| `Dough` | 面团 | Dough |
| `Yeast` | 酵母 | Yeast |
| `Alcohol` | 酒精 | Alcohol |

`DT_DWRecipes` 也有 `DisplayName` 和 `EnglishDisplayName`。现有 `CraftDough` 对应“面团 / Dough”，`CraftAlcohol` 对应“酒精 / Alcohol”。输入、输出数组继续使用固定 `ItemId` 与数量，语言不会改变配方消耗或产量。

新物品英文名未填时，英文界面会显示 `ItemId`；新配方未填时通常显示 `RecipeId`，已知默认配方有对应英文兜底。填写明确的英文显示名可以避免将内部 ID 显示给玩家。已有默认物品/配方的旧数据表尚未填写英文字段时，配置读取逻辑会给已知 ID 补充默认英文；新建自定义物品仍应自己填写。

修改表格后保存，并重新进入游戏会话检查。玩法配置 `DA_DoughWorldGameplay` 的 `Item Table` 和 `Recipe Table` 应继续引用你实际修改的表。

对后续新增的固定 UI 文字，当前系统不会自动翻译任意中文。程序需要给新文字增加中英文对照，或在自己的蓝图中根据语言填入两种文本。当前静态 UI 对照文件为 `DWLocalizationCatalog.inl`；程序可以通过 `DWLocalizationLibrary` 的 `Get Language` 查询当前语言，并使用语言变化通知刷新自定义界面。不要将新内容写死为只有一种语言的文字后直接交付。

## 10. 常见问题

| 现象 | 检查方法 |
|---|---|
| 中文是方框，英文正常 | 主 UI 检查 HUD 的 `Game UI Font`；提示检查 Style 的 `Title Font`，确认使用覆盖中文的组合字体。 |
| 靠近资源没有提示 | 先开始游戏；确认玩家存活、无暂停/阻挡菜单，资源可采集并且成为当前采集目标；检查资源的 `Interaction Radius`。 |
| 靠近普通 Actor 没提示 | 检查组件是否启用、Actor 是否隐藏、组件是否挂在现有根节点下，以及 `Generic Detection Radius`、`Height Tolerance` 和默认 WBP 是否存在。 |
| 提示偏低或穿进模型 | 改组件 `World Offset.Z`。改 `Float Distance` 只影响动效，不改变空间锚点高度。 |
| 提示出现但按 F 无反应 | 普通 Actor 的提示组件不带交互逻辑；确认另有实际输入和动作实现。资源则检查背包空间、资源可用性和玩家采集条件。 |
| 同一物体有两套上方文字 | 检查是否在已自动继承 `InteractionPrompt` 的资源上，又手动添加了一份。 |
| 上方和屏幕底部都显示采集文字 | 关闭 HUD 的 `Use Legacy Interaction Prompt`。 |
| 没有提示声音 | 检查 Style 的 `Appear Sound`、音量、组件的 `Play Appear Sound` 和游戏主音量；短时间切换目标可能被冷却抑制。 |
| 换了 Style 字体但 Designer 预览不完全一致 | 以游戏运行时应用的 Style 为准；修改后保存并重新进入会话观察。 |
| 某个自制物体仍显示中文 | 补填组件英文标题/动作；资源名称则补填物品表 `EnglishDisplayName`。新增固定 UI 文本需要补充翻译对照。 |
| 重启后语言没有保留 | 检查当前运行实例实际使用的 `Saved/Config/DoughWorldPreferences.ini`；编辑器与打包运行不一定共用同一 Saved 目录。 |

程序排查可在组件实例详情查看 `PromptShownCount`、`PromptHiddenCount`、`SoundPlayCount` 和 `PresentationOpacity`。声音计数只记录实际触发播放的次数，被冷却抑制的声音不计数；提示退出动画尚未结束时，可见透明度可能仍大于零。

## 12. 设置各类交互声音

除物体上方提示的弹出音外，游戏操作声音统一放在 `Content/DoughWorld/Maps/Gameplay/Data/DA_DoughWorldGameplay` 的 `Audio` 分类。把导入的 Sound Wave 或 Sound Cue 拖到对应槽位即可。当前 `UIClickSound` 和物体上方提示的 `Appear Sound` 已配置本轮原创键盘声；多数新增专属槽位仍留空，空槽静音，后续可逐项填入合适的音效。

| 分类 | 声音槽位 | 触发用途 |
|---|---|---|
| UI | `UIClickSound` | 普通按钮点击 |
| UI | `UISelectionSound` | 选择背包物品或合成配方 |
| UI | `UIFailedSound` | 存档等普通界面操作失败 |

| Inventory | `ItemUseSuccessSound` / `ItemUseFailedSound` | 使用物品成功 / 失败 |

音量和音高按用途分组：`UIClickVolume` / `UIClickPitch` 影响普通点击；`UIEventVolume` / `UIEventPitch` 影响其他界面事件；`GatherSoundVolume` / `GatherSoundPitch` 影响采集各阶段。音量范围 0 到 1，音高倍率范围 0.5 到 2。需要让某个音源单独更轻、更短或更高时，可为该槽使用独立的 Sound Cue 调整；无需复制整份玩法配置。

原有 `MenuBGM`、`GameplayBGM` 和 `MusicVolume` 继续负责背景音乐。物体上方的键盘弹出音仍在交互 Style 的 `Appear Sound` 中，两处各负责自己的用途。

声音触发由既有操作流程统一负责：HUD 处理页面进入/离开，界面处理点击、选择和操作结果，玩家处理采集。给蓝图加美术表现时，不要再在同一事件里重复播放已经配置的声音。代码侧的统一入口为 `DWAudioLibrary → Play Event`；它只播放声音，不执行采集、合成或物品使用。

采集循环由玩家持有音频组件并管理停止和销毁。松开按键、失去有效目标、打开阻挡菜单、死亡或离开关卡时应结束循环。音源本身可以是循环 Sound Cue；短的非循环音源由采集播放逻辑在仍有效采集时重新播放，不修改原始音频资产的循环标记。

28 个声音事件的空槽与配置后分发、采集循环停止和释放已通过专项 PIE 检查，48 项交互回归也已通过，证据见第 11 节和本轮交付报告。音效接口已接通不表示每个槽位都有最终声音素材。

## 13. 橙色变身体型调整

在内容浏览器打开 `Content/DoughWorld/Maps/Gameplay/Blueprints/BP_DWTopDownCharacter`，选择 **Class Defaults（类默认值）**，在详情中找到 `DoughWorld → Transformation → Visual`，或直接搜索下面的参数名。修改后编译、保存蓝图，再启动游戏会话检查。

变身视觉由形态状态持续控制。进入酵母形态时，角色体型与颜色一起平滑变化；默认放大为原始体型的 **1.36446 倍**，颜色变为橙色。变身动画播放结束后，待机、行走和其他动作继续保持放大后的酵母外观，直到玩法状态退出酵母形态。恢复面团形态时再平滑缩回原始尺寸和原材质色调。

| 参数（代码名） | 默认值 | 调整用途 |
|---|---|---|
| `YeastFormScaleMultiplier` | `1.36446` | 酵母形态的最终体型倍率；`1` 为角色原始体型。 |
| `YeastTint` | 线性 RGBA `(1, 0.36, 0.065, 1)` | 酵母形态的橙色材质倍率，可在颜色选择器中调整。 |
| `DoughTint` | `(1, 1, 1, 1)` | 面团形态材质倍率；默认保留原贴图颜色，并非将角色涂成纯白。 |
| `Match Form Enter Blend To Animation`（`bMatchFormEnterBlendToAnimation`） | 开启 | 让进入时的体型和颜色过渡时长跟随 `TransformAnimationSeconds`。当前主角蓝图的动画窗口约为 `1.6333333` 秒。 |
| `FormEnterBlendSeconds` | `1.6333333` 秒 | 关闭上一项后，可单独调整进入酵母形态的视觉过渡时长。 |
| `FormExitBlendSeconds` | `0.45` 秒 | 退出酵母形态、恢复原始体型和颜色所用时长。 |
| `FormBlendExponent` | `2` | 进入和退出的缓动曲线强度；`1` 为线性过渡，更大数值使首尾变化更缓。 |
| `Compensate Transform Root Scale`（`bCompensateTransformRootScale`） | 开启 | 抵消动画当前根骨骼自带的缩放，避免与持续体型倍率叠乘。使用当前主角动画时保持开启。 |
| `FormScaleRootBone` | `root` | 用来识别整体缩放的根骨骼名称；更换骨架后才按新骨架调整。 |

原始变身动画将 `root` 骨骼从 `1` 放大到约 `1.36446`，而待机、行走的根骨骼缩放为 `1`。补偿功能读取当前实际骨骼姿态，而不是只根据正在请求播放的动画名称判断，因此动画切换边界仍保留必要的缩放补偿。无需修改或重新导入现有动画；不要再给相同变身事件额外叠加一次 Mesh 或 Actor 放大。

这里调整的是角色可见模型及随骨骼附着的物件。原有骨架朝向、Mesh 位置、贴图、碰撞胶囊、摄像机、移动速度和采集范围继续使用各自的原有配置。

存档已经保存形态及变身值。当前源码的加载逻辑会在有效酵母形态存档恢复时直接设置对应的放大体型和橙色视觉，不要求先重播变身动画，也不再次发放变身奖励；恢复面团形态时设置原始尺寸与色调。存档不额外保存一份动画中间帧缩放。这里说明的是已实现的恢复逻辑，本轮尚未对“加载酵母存档后恢复橙色和体型”单独进行 PIE 验证。

程序排查可读取玩家实例的 `CurrentFormVisualScale`、`CurrentFormBlendAlpha` 和 `CurrentAnimationRootScale`，或调用 `GetCurrentFormVisualScale()`。变身动画内部带缩放时，Mesh 的单独缩放值可能与最终视觉倍率不同，需要结合根骨骼的实际缩放判断；不能仅凭 Mesh Scale 判断角色是否维持放大。

持续橙色、约 `1.36446` 倍体型和逐帧动画缩放衔接已通过 [RuntimeTransformAudioQA.json](RuntimeTransformAudioQA.json) 的专项 PIE 检查。存档恢复外观仍按上一段保留独立验证边界；完整证据与最终回归结论见[《本轮交付与验证.md》](本轮交付与验证.md)。
