修复了哪些问题

问题 本次修复与结果
组员同步后 C4459 编译失败 Unity 合并编译把多个 cpp 放入同一编译单元；测试中的 Panel、Names 与其他文件的匿名全局标识符重名，触发六处 C4459。现在改为各自专用名称，强制 Unity 下 Editor/Game 构建均成功。颜色值、设置键、字符串和资源路径不因重命名改变。
编译失败后小地图未显示 这是可能仍加载旧 DLL 的后果。本版修复源码构建冲突；组员需要 Pull 后重新生成 Editor DLL，小地图本身没有新增功能。
读档切换时可能覆盖目标槽 活动槽已切为目标槽时，旧关卡玩家仍可能存在。SaveCurrentGame 在读档、角色恢复或转场完成前返回 false，保留目标存档；完成后恢复正常保存。
关闭加载动画切图后一直不能保存 修正直接切图分支的内部旅行状态收尾，使切图完成后正常恢复保存。
合成/变身提示错误要求先变身 提示现在同时遵循现有 Require Transformation For Crafting 总开关和配方 bRequiresYeast；总开关关闭时，不再错误提示必须先变身。材料/容量检查及既有配方规则保留。
演示文字控件 C4305 浮点截断警告 DWTextRevealDemo 的颜色常量明确使用 float（f 后缀），消除该处警告，颜色设计不变。
回归检查补充 增加隔离目标槽字节保护、加载后恢复保存、无动画切图的回归检查；QA 报告使用实际活动槽。这是验证补充。

组员如何同步并让修复生效

  1. 在 UE 保存需要保留的工作，并关闭编辑器。先保护自己的未提交修改，避免拉取时冲突。
  2. GitHub Desktop 选择 Art-TechGroupWork → main → Fetch origin → Pull origin。使用最新版 main；旧 v0.3.0-alpha.1 标签不会自动变化。
  3. 右键自己目录的 GDATtest.uproject → 显示更多选项 → Generate Visual Studio project files。
  4. 打开 GDATtest.sln；Visual Studio 选择 Development Editor / Win64，在解决方案资源管理器右键 GDATtest → Build（生成）。它对应 GDATtestEditor 目标。生成项目文件不等于编译，Development 游戏目标不能代替 Editor DLL。
  5. 等待生成成功且无 error，确认 Binaries/Win64/UnrealEditor-GDATtest.dll 修改时间更新，再双击 .uproject。
  6. 进入现有 Map1：检查右下小地图、中键转动跟随，以及设置中的五个书签。使用自己的测试存档检查加载结束后保存；不要在读档/转场过程中把失败返回值当成保存成功。

蓝图开发者调用 Save Current Game 后，用 Branch（分支）检查返回值：true 才显示成功；false 从 Last Save Error 获取原因。现有保存 UI 已处理返回值，不需要重建控件。合成总开关仍位于 DoughWorld/Core/Data/DA_DoughWorldGameplay → Crafting → Require Transformation For Crafting。

若仍报 C4459，先核对是否拉到了本版、是否重新生成 Editor DLL，并保留完整构建报错。不要运行旧交付安装脚本覆盖当前源码，也无需删除 Content、Saved 或存档。

新增：可复用小地图及目标导航

  1. 右下增加圆形小地图，宽度与右上 BrewingCard 对齐；暖白几何体块、纯白圆框、玩家青色、资源/点位金黄、敌人珊瑚红，标记带白色细描边。
  2. 底图来自当前关卡实际几何的深度捕获，不使用固定 Map1 图片。玩家移动和场景模型变化会更新底图；默认 Capture Interval=0.2 秒，Capture Resolution=1024，View Radius=5000 cm（50 米）。
  3. 默认 Follow Camera Yaw=True：底图、玩家箭头、标记和圈外方向一起跟随主镜头水平朝向。四个方位字母绕圆圈变化且保持正立。关闭该参数可恢复固定朝向，North Yaw 默认 0°。
  4. 圈内突出当前导航目标，圈外显示边缘方向箭头；目标信息使用水平直线米距离，不表示绕障碍的寻路长度。
  5. 小地图沿用暂停/过场显隐和 DW UI Offscreen 动画。切图后重建当前 World 对应的显示与导航状态。
  6. 新增可编辑组件 BPC_DWMinimap、BPC_DWMinimapMarker，以及 WBP_DWMinimap 和 M_DWMinimapClay；现有 Hero 仅局部添加 MinimapController。

编辑入口： 内容抽屉 → DoughWorld/Characters/Hero/Blueprints/BP_DWTopDownCharacter → 双击 → Components（组件）选 MinimapController → Details 搜索 Follow Camera Yaw。组件蓝图位于 DoughWorld/Gameplay/BPC_DWMinimap；改以后新组件的默认值时使用 Class Defaults（类默认值），既有实例覆盖值仍优先。North Yaw 定义世界北方，Capture Pitch 默认 −70°，不会跟随主镜头上下拖动。

  1. 设置重排为图像 Graphics、声音 Audio、按键 Keys、控制器 Controls、常规 General 五个固定书签，使用暖奶油纸页、焦糖圆角和深棕文字。

  3. 所有滑条采用统一较粗样式：Slider Track Thickness 默认 8，Slider Thumb Size 默认 22×22，单位为 UMG 逻辑尺寸。
  4. 控制器页显示实际生效的动作绑定和背包组合键说明，新增 Camera Sensitivity 灵敏度调节。按键页继续提供改绑和恢复默认；切换书签会取消正在等待的改键操作，避免把导航点击误绑为按键。
  5. 图像选项沿用 Apply & save（应用并保存）；音量、灵敏度、成功改键和语言即时保存。常态控制说明移入设置页，原控件名称和绑定保留。

玩家入口： 主菜单 Settings；局内按 P → Settings。默认 Esc 也可暂停，但在编辑器 PIE 可能直接停止试玩，验证时使用 P。

  • 默认 Key Camera Drag 从鼠标右键改为 Middle Mouse Button（鼠标中键）；按住中键拖拽改变镜头。
  • 设置 → Controls 可调玩家灵敏度倍率，范围 25%～300%，默认 100%；倍率作为本机设置保存。
  • 滚轮向上拉近、向下拉远；暂停、过场和菜单期间阻止玩法镜头输入，滚动说明页不会同时缩放主镜头。

新增：背包分堆、合并与丢弃确认

按 B 打开背包，制作页的背包区域也支持以下操作：

操作 默认输入 行为
选择物品 左键 显示用途
拖动整组 左键按住拖动 同类格合并，不同类交换顺序
拆出 1 个 右键 放入新空槽
拆半 Shift+右键 拆出向下取整的一半
快速堆叠 Shift+左键 合并背包内同类可合并堆叠
丢弃整组 选中后 Delete，或 Ctrl+左键 弹出确认
拖出丢弃 拖到背包外、游戏窗口内的区域 在松手处旁弹出确认

确认窗为 260×128 逻辑尺寸，仅显示“是否丢弃？是/否”，靠近屏幕边缘自动向内调整。是/Enter 确认；否/Esc/点击小窗外取消。取消不扣物品；拆分失败不改数量。确认丢弃后不会生成地面可捡拾物品，之后正常保存会记录库存删除结果。

编辑入口： WBP_DWGameplay → Class Defaults → Inventory → Input，可改 Drag Button、Discard Key、Discard Click、Quick Stack Click、Split One Click、Split Half Click。各组合严格区分修饰键，不应配置成相同组合。背包容量与单堆上限仍由既有物品配置控制。

新增：合成变身要求总开关

DA_DoughWorldGameplay → Crafting 新增 Require Transformation For Crafting / 合成是否需要变身。当前默认关闭，普通形态也可合成；开启后，配方原有 Requires Yeast 规则重新生效。材料和背包容量检查始终保留，不会因为关闭变身限制而免费合成。最新包已验证未变身实际合成成功及开关两种状态。

编辑入口： 内容抽屉 → DoughWorld/Core/Data/DA_DoughWorldGameplay → Details → Crafting；保存当前 Data Asset 后重新运行。

新增：对白左键直接下一句

保留自动逐字播放、逐句停留和自动换句，增加每次左键直接下一句。最后一句点击后跳过额外字幕展示等待；若断桥等场景事件仍在执行，继续等待事件完成，再恢复镜头、HUD 和玩家操作。跳句不等于取消整个场景事件。

编辑入口： 地图中选中过场 Actor → Details → Cinematic → Subtitle → Allow Click to Next Line，默认开启。关闭后保持自动流程。蓝图可调用 Skip Dialogue Line / Skip Subtitle Line；原 Advance Dialogue 接口保留。

修复：重复资源点导致保存失败与文档存档目录

  1. 修复两个面粉资源点共用 Prototype_Flour 产生重复场景记录，导致提示“invalid or duplicate world object records”的问题。复制物件现在用对象路径分别保存和恢复，现有地图及原 ID 保留。
  2. 存档格式由上版 3 升为 4，增加 ActorPath / OwnerPath；读取接受 1～4。旧记录 ID 唯一时可以匹配；后来改地图/对象身份或令旧 ID 变得重复的历史档，仍需单独迁移验证，不能保证任意地图变更兼容。
  3. 打包 Windows 游戏启动后自动创建当前用户 文档/DoughWorld。解析 Windows 文档已知目录，支持不同用户名、盘符和重定向；本机是 D:/文档/DoughWorld。
  4. Edit → Project Settings → Project → DoughWorld Saves → Save Location → Documents Folder Name 可改文件夹名称；默认 DoughWorld，只填一层名称，支持中文，非法名称回退默认。重新打包生效，改名不自动搬移原存档。
  5. 三槽统一使用该目录保存、读取、摘要和游戏内删除。写入先生成同目录临时文件再替换，失败不先删上次存档。
  6. 新目录首次检查当前安装可访问的旧槽，复制时保留源文件和已有目标，用 .legacy-import-v1 标记防止以后删除的旧槽重新导入；不扫描所有旧包。

资源点维护： 选中地图资源实例 → Details 搜索 Persistent → Resource → Identity → Persistent Id。后续新点推荐 Map1_Flour_001、Map1_Flour_002；Item Id 仍为物品种类 Flour，不改成实例编号。已发布对象保持地图路径、Actor 身份和 ID 稳定；清空 Persistent Id 会回退对象名，不是关闭保存。

删除存档： 主菜单 → Start game → 对应槽 Delete → 再点 Confirm delete，成功后显示空槽。只删当前目录那个槽；编辑器、旧包和备份是独立文件。手动清空前退出游戏，只删 DoughWorld_Final_Slot_1/2/3.sav，保留 .legacy-import-v1。UE PIE 仍用工程 Saved/SaveGames；画质、键位、音量等本机设置仍沿用 UE 设置目录。个人存档不纳入仓库。
